## 已实现

- `005-management-rules.sql` 新增六张本机表：配置修订号、逐项规则覆盖、公司日历、状态映射、职能不适用确认、首次计划基线；扩展来源绑定的工作流状态元数据。仅前向迁移，不改已有迁移，不重置数据。
- 系统默认 → 版本覆盖 → 需求级覆盖。按项显示生效值和来源，只保存例外；恢复继承移除该项显式覆盖，上层后续修改继续生效。基础流程和细节完整职能不能重叠，保存上层时也检查下层组合；开发关注阈值仅系统默认可修改，初值 3。
- 基础流程默认 UI、美术、数值、客户端、服务端、KGUI；细节完整额外默认动效、后台。采集时间默认周二、周四 10:00，使用北京时间，仅公司工作日命中；本批不发送通知或补发消息。
- 默认周一至周五为工作日，允许配置休息日、调休或特殊工作日，允许恢复默认周历。计划周期、到期与实际计时使用同一日历。日期级计算，不推断半天或实际工时；单段超过十年的范围暂停计算并提示核对。
- 七项管理语义与四类独立计时节点按来源项目和状态 ID 保存。来源 ID、名称和历史保持原值，列表显示工作流及当前任务使用数量。允许部分映射，未映射不是第八项语义。保存后待验证恢复；必须重新成功读取来源并通过校验，才记录映射恢复验证通过。
- 管理接口先做当前登录权限及 Origin/CSRF 检查，配置事务再次核对当前管理员权限。预览不写库；保存须携带预览修订号和来源快照摘要。预览后配置或来源变化会拒绝过期保存，要求重新复核。保存和映射恢复验证均留审计。
- 所选职能没有工单时，不自动视为完成。当前不适用确认由已确认的版本负责人本人操作，同时须具备管理员或所有者权限；业务职责本身不授予后台写权限。已有当前或历史工单的职能不能借不适用隐藏来源缺失或未完成事项，可撤回确认。
- 基础流程检查所选核心专业子单，细节完整累计基础及额外职能。测试阶段固定检查全部应处理后代，不能裁剪类型。未知状态、来源不可用和相关结构缺失不算完成；重开后按当前成功快照回退。非交付终态可以收口，但单列且不计实际交付。
- 版本按核心需求等权汇总，不按子单数量加权。存在待核对需求时，相应完成百分比为未知，不能填零。优化需求自身终态计数与直属任务的完成门槛分别计算，未知也分别保留。
- 开发、测试计时只读取已保存且结构可核对的 `update.taskflowstatus` 来源动态，使用来源发生时间。同步起点前不补造过程；系统观察时间和计划时间不作为实际起点。保留轮次、本轮与累计工作日、重开次数。暂停、处理中但不计时、其他非对应计时语义不累计；终态缺少必要结束节点、事件断链或缺少开始证据时记未知。
- 日期边界：进入非计时状态的当天不新增累计日期，恢复到对应计时状态的当天可累计；结束节点关闭此前有效计时段，同日开始并结束且为工作日时计一天。跨段同一工作日只在该轮计一次，不录入半天或小时。
- 跨全部活跃版本，按来源实际执行者 ID 汇总核心专业子单计划区间的工作日重叠。仅使用系统阈值；缺少执行者或计划的任务单列排除数。结果是管理复核提示，不代表超载、实际投入或绩效。
- 首次计划须由当前版本负责人核对证据、预览后显式确认，不自动把当前计划当首次计划。现有基线不会被后续同步改期覆盖，缺失日期保持空白。业务账号只可读取、插入基线，不能更新或删除；有证据的后续纠错界面仍按 P09 实现，不提供绕过入口。
- 配置及计算读取使用一致的数据库快照，展示最近成功同步时间。来源读取失败保留旧快照并提示，不能把旧快照说成实时事实。

## 当前会话人工验收步骤

1. 刷新 `http://127.0.0.1:4310/` 并登录，找到“P05 · 规则与阶段验收”。应看到受控调试版本、1 个核心需求及 14 张任务；映射未配置时显示待核对和未知，这是预期保护。
2. 展开“状态语义与计时节点”。默认优先展示当前任务使用的状态，可切换全部工作流或指定工作流。当前任务全部处于“待处理”，依据既定工作流规范，可逐行核对并选“未开始”，不勾开发/测试计时标记。填写原因，预览影响后保存。不要把“开发完成”“测试完成”一律映射为交付完成。
3. 保存映射后，先点击上方“读取来源并同步”，完成后再点“验证映射恢复”。预期从待验证恢复变为验证通过；任务仍是未开始，不能因此显示阶段完成。后续读取到其他状态时继续按对应工作流规范核对，未配置的状态仍暂停相关判断。
4. 展开分层规则，在版本层调整一项采集时间，预览并核对影响范围后保存；检查来源显示版本覆盖。随后在该项勾选恢复上层继承，再预览保存，检查回到系统来源。下层开发关注阈值必须只读；重叠职能须拒绝。取消预览时数据库不变。
5. 按实际交付范围检查基础及细节职能。缺少工单的职能只有确实不适用时才由已确认版本负责人本人确认，不能为使阶段完成而忽略实际范围。没有证据时保持待核对，不强行通过。
6. 首次计划只在已核对版本纳入时计划证据、确认当前值与首次计划一致后保存。不能确认时保留待确认。空白计划和缺少状态开始记录仍为未知，不用计划时间代替实际时间。
7. 如需人工核验状态回退或计时，仅在已批准调试迭代内操作用户自己的测试任务，并先明确相关状态语义和节点。全部阶段收口测试需要范围完整；单张子单完成不能证明整个核心需求完成。本轮不要求修改任何正式版本。
8. 吴潇靖应可查看配置和计算，无保存入口，写接口仍拒绝。完成后在当前会话反馈 P05 验收结果。本批人工验收通过后，再交接 P06–P08 新会话；不为提交或推送另开会话。
