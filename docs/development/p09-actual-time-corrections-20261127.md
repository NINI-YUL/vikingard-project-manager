## 已确认规则与实现

- 入口：核心需求详情 → 工单时间线 → 点击工单 → 修改实际时间。只操作具体工单，不覆盖核心需求汇总时间。
- 以北京时间日期为单位，分别选择开发／测试阶段与轮次；默认当前阶段最近一轮。开始、结束均支持跟随 TB、指定日期、清空为未知。切换阶段和轮次保留尚未提交的草稿；取消不写库。
- 原因和依据必填，保存前展示前后日期、作用对象和影响；服务端重新校验权限、日期及来源快照。
- 用户明确取消“实际日期不能晚于今天”的限制：可保存未来开始、未来结束；仍检查合法日期和结束不早于开始。未来开始不绘实际线，不以当前或预估时间填补空值。
- 管理员、所有者可保存；查看者只看实际时间与修正历史。每次写入重查当前有效身份和系统权限，并检查 Origin、CSRF。
- 修正表独立于 work_items、source_activities；来源原始事实不改，工单状态、完成门槛和预估条不改。来源值与当前人工值并列展示。
- 未覆盖字段持续跟随 TB。例如只补开始，原轮次后续出现 TB 结束记录时直接采用新结束。
- 被覆盖字段的 TB 日期后来与人工值不同，保留人工值并提示来源变化；同日值不冲突。提供保留人工修正、逐字段恢复跟随及整条恢复来源，并保存审计。
- 轮次以来源事件 ID 及起止边界关联，不以数组序号关联。重开生成的新轮次不继承旧修正；补入历史造成轮次拆合、边界无法确定、已存事件不再属于原轮次时，标待核对，不自动套用。用户可明确重新关联到目标轮次，或恢复来源。
- 完全没有来源轮次时允许补日期。之后出现来源轮次时，因为无法自动证明是历史回补还是新一轮，需重新关联核对；不会自动挪用人工记录。
- 来源更新与人工组合导致日期倒置时，保留最近已保存或成功同步确认的有效结果，并提示核对。同步在自己的事务内更新有效结果缓存；原始来源历史仍保留。
- 暂停和公司日历仍由既有来源计时计算。日期变化不能证明执行过程，因此历时标待核实，不沿用修正前总历时，也不直接累计区间内全部工作日；来源日期未变且原始计时可核实时保留既有历时。
- 人工结束存在、工单仍未终态时，显示“实际已结束，状态未完成”，不增加完成圆点。只有实际结束存在且工单终态时显示完成圆点。
- 修正、同步使用相同版本互斥锁；写事务依次取得版本锁、当前身份锁、管理规则锁，避免保存与同步交叉提交。快照包含同步游标、管理配置版本和修正版本，旧表单返回 409。
- 审计包含原来源日期、修正前后值、阶段、来源事件、操作者、时间、原因、依据、重新关联与恢复信息；编辑窗口可查全部修正历史。
