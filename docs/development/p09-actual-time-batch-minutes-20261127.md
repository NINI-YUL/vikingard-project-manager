# P09 实际时间修正：多轮提交、时分与完成工作日

日期：2026-11-27（北京时间）。延续 codex/p09-management-pages。

## 用户确认的调整

1. 编辑窗口只保留修改原因，取消依据输入。历史依据继续保留在审计中，不删除旧证据。
2. 同一工单可在一次编辑中调整多个开发／测试轮次。阶段和轮次切换保留草稿，预览展示全部改动，一次确认保存；一个轮次无效时全部不保存。
3. 对“历时待核实”保留事实解释。人工起止发生变化，不能证明中间执行和暂停记录完整；日期或时分填写完成不自动表示过程已核实。若来源时间正确，可以恢复使用 TB 时间；若人工时段正确，仍需核对相应执行与暂停证据。
4. 已完成任务在可计算时显示“已完成 N 个工作日”。继续采用公司日历、暂停扣除和既有多轮累计，不把各轮取整后的工作日直接相加。未知不填零，人工区间未核实时仍显示“已完成 · 历时待核实”。
5. 手工时间支持北京时间日期、小时和分钟；允许未来时间。同一天结束早于开始会被拒绝。旧的仅日期记录明确标记“时分未提供”，未编辑的旧值不被擅自补齐或截断。

## 实现

- app/actual-time-engine.mjs：读取精确时间并兼容历史日期值；完整时间按时刻判断顺序，日期旧值保留原精度；新记录按完整来源时刻识别同日内的来源冲突。
- app/actual-time.mjs：在既有 API 接受 changes 数组，1–100 个轮次共用一个修改原因、快照和事务。先校验全部改动及最终轮次占用，再写入和追加审计；每批使用共同 batchId 关联审计。
- 保留旧的单轮请求格式和可选 evidence 字段。新表单不再发送 evidence，已有审计中的 evidence 保持不变。
- app/public/shell.js：日期与时间控件、全工单草稿和修改轮次数、批量预览、单次提交；源时间和当前值展示到分钟，已完成文案补充工作日。
- app/public/shell.css：复用既有浅色 Token 和固定头尾弹窗，仅增加日期与时分网格、批量预览分组。
- app/server.mjs：请求体限制调整为 64 KiB，能力接口增加 actualTimeBatch。新页面在旧服务尚未更新时禁用该入口，防止向旧接口发送新格式。
- 复用 actual_time_corrections 的 JSON 数据结构，没有新增表、字段或数据库迁移。所有原始 TB 事实、预估时间、工单状态和完成规则保持原口径。
