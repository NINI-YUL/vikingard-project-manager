## 真实读取与数据保护

`app/main.mjs` 将真实来源适配器传给 createApplication。每次触发从后端调用固定只读命令，不再依赖聊天中的手工快照。

1. 核对 Teambition 企业、项目和迭代的真实关系，名称由来源读取，不接受浏览器伪造名称。
2. 读取任务类型及其工作流，按工作流分别读取状态定义。若存在后续定义页却无法完整获取，则整体失败；不把默认 50 条状态误当成完整配置。
3. 核对 `工单分类` 与 `职能` 两个真实字段 ID、名称和单选类型。任务类型/状态按稳定 ID 补全名称。
4. 任务查询在服务端同时限定项目、迭代和非归档范围，按分页游标继续读取。逐条再次校验来源范围，拒绝重复或缺失任务 ID。不透明游标允许重复，但不能无限读取空页或重复任务；页数与任务数有上限。
5. 检查完整快照的父子关系。缺失父任务保留任务并标记；自循环、多级循环及非法快照拒绝写入。缺职能的子需求保留展示；任务和优化需求等允许不填职能。
6. 同一版本的同步通过数据库事务锁互斥；来源失败或快照失败不覆盖已有事实和最近成功时间。成功时原始状态 ID、来源对象及当前值一并保存。
7. 来源绑定持久化到 source_bindings，包含类型/状态名称表、字段 ID 和核验时间，定义变化会提升项目配置版本。
8. 版本纳入、负责人确认和同步结果均写操作人、原因与结果审计。来源调用前校验权限，提交事实前与撤权共用安全锁再次校验；读取期间撤权时不提交本次结果。

CLI 子进程不使用 shell，隐藏窗口，单次命令有超时及输出上限。CLI 成功响应既可能是包含 code=200 的 MCP 结果，也可能只有 requestId/result；适配器均处理，但非零退出、显式错误、无结果及格式错误必须失败。不输出上游 stderr、完整异常或授权信息。

## 权限及验收入口

按操作手册，版本纳入属于管理员业务操作。业务负责人和系统角色分开维护；选择版本负责人不会授予后台权限。

| 接口 | 权限与作用 |
| --- | --- |
| GET /api/versions | 查看者及以上，查看已保存版本、负责人、同步起点、结果和绑定核验状态 |
| GET /api/versions/:id/tasks | 查看者及以上，分页查看已保存任务，每页 100 张，不返回来源原文及凭证 |
| GET /api/source-candidates | 管理员及以上，仅返回已批准且核对成功的来源迭代 |
| GET /api/version-people | 管理员及以上，仅列当前企业已确认、有效的身份人员，用于显式选择业务负责人 |
| POST /api/versions | 管理员及以上，选择负责人并填写原因；同一版本不重复建立跟踪区间、不重置同步起点，负责人变更另记审计 |
| POST /api/versions/:id/sync | 管理员及以上，填写原因后触发后台真实只读同步；失败结果明确返回 failed |

所有写接口继续核对 Origin 与 CSRF。查看者页面没有版本确认和同步按钮，直接调用写接口仍被拒绝。来源标题等内容通过 textContent 展示。手机端表格在区域内横向滚动，不把文字压成逐字竖排。

原先已导入版本的业务负责人未由用户指定，因此保留待确认，未自动把余莉的系统所有者身份当成版本业务负责人。请在本机验收表单显式选择并确认。
