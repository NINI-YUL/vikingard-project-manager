## 保留数据的部署办法

沿用当前工作区和 F:\VikingPM 环境。其他已有环境部署时，先使用现有备份流程保留数据库副本，停止应用，再运行以下命令，成功后启动应用并检查 healthz：

~~~powershell
& 'C:\Program Files\nodejs\node.exe' scripts/application.mjs migrate
~~~

006 是前向增量迁移，不执行重置、删除或拆分工单；重复运行跳过已应用迁移。历史 function_name、raw_source、工单 ID、来源快照及配置保留。function_options 是来源字段实际选项快照，需要下一次成功读取来源后填充。不要直接修改已应用迁移的内容或校验记录，也不要通过删表、删列处理回退；如需恢复，先保存新增业务数据，再在隔离恢复库核对备份后决定恢复范围。

本机已应用 006。最后核对有 14 张工单：6 张职能已确认（UI界面、动效、数值、客户端、服务端、KGUI 各 1 张），8 张职能未填写；没有旧 UI 工单，没有复制或删除工单。缺失职能不等于全部都是异常工单，须结合工单类型判断是否必填。

来源字段实际选项快照为 客户端、服务端、策划、动效、UI界面、数值、KGUI；尚无 UI图标、美术、后台。策划若出现在工单职能值中，会保留原文并标记来源值待配置。程序没有向 TB 写入选项、工单或通知。
