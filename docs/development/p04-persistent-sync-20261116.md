## 实现范围

- 新增 `004-persistent-sync.sql`，保存到期时间、失败次数、任务来源存在状态、执行关联、计划日期、来源完成时间、来源动态修订及系统观察记录。
- 应用启动立即检查到期版本，随后每 30 秒检查一次。业务库保存到期时间与成功检查点；重启后重新读取到期状态。本机试用同步间隔为 900 秒，该间隔不是同步时效承诺。
- 只读取配置允许的企业、项目和调试迭代 `6af6dc04343bbec69ee63070`。只有已纳入且业务负责人身份已确认、启用的版本参与自动轮询。业务负责人未选择时暂停，不自动使用系统所有者代替。
- 自动与手动同步共享 PostgreSQL 版本锁。提交前重新检查权限；自动执行审计使用空 actor_id 和明确的“系统轮询”原因，不冒充负责人。
- 当前任务事实、来源动态、观察记录及成功检查点在同一事务提交。读取失败、分页未完成或结构异常保留上次成功事实、游标和成功时间，并记录失败与重试时间。失败重试从 60 秒递增，上限为配置同步间隔。
- 成功检查点是本系统成功同步运行 ID，不是 TB 增量游标。目前每轮完整读取受控迭代及当前可见动态，不假定来源提供可靠的增量历史。
- 缺失旧任务逐项读取详情，分别记录归档、移出范围、明确拒绝访问、原因未知和明确删除。403 仅表示访问受限；404 或空结果仍为原因未知。不会据缺失直接推断隐私或永久删除，也不会删除已有事实。
- 来源动态按稳定来源 ID 加内容修订摘要保存；重复读取不新增相同修订。系统观察仅在管理字段发生变化时新增，A→B→A 保留三次观察。观察时间不能当成真实状态流转时间。
- 新增已登录用户可读的分页历史入口，页面区分来源动态和系统观察；不向页面返回原始上游动态内容。业务账号对两张历史表只有读取、插入权限，没有更新、删除权限。
