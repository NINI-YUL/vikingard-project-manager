# 钉钉 AI 表格收集表单调研

日期：2026-09-03

## 调研范围

本调研用于判断能否以钉钉 AI 表格收集表单替代互动卡片，作为开发人员提交任务进度的入口。重点核对表单创建与分享、提交落表、提交人和时间、预填参数、重复提交、权限与有效期、自动化及 API 读取能力。

结论只采用钉钉官方页面、钉钉开放平台文档和第一方 SDK；未找到官方明确说明的能力一律标记为待实测，不把产品界面可能存在的选项写成既定能力。

## 关键结论

- 钉钉 AI 表格官方帮助中心把表单列为数据收集能力；官方最佳实践明确演示了创建表单视图、分享表单链接、员工提交后将记录自动沉淀到 AI 表格。因此以收集表单替代互动卡片作为填写入口有直接的一手依据。[AI 表格帮助中心][ai-table-help] [记录、视图与表单][records-views-forms] [表单自动化最佳实践][form-automation-practice]
- 官方最佳实践以“创建记录时”为自动化触发节点，随后更新记录和发送钉钉消息；因此“表单提交后触发记录型自动化”已在官方场景中确认，但本项目的具体条件、动作、重试、身份上下文和免费额度仍须实测。[表单自动化最佳实践][form-automation-practice]
- AI 表格官方帮助中心明确提供表单预填默认值 URL 规则，支持文本、数字、单选和多选字段。工单 ID 可以作为文本字段通过任务专属链接预填，但预填值仍需在 PoC 中验证，且不能当作不可篡改的任务身份凭据。[表单预填默认值][form-prefill]
- 官方 Notable API/第一方 SDK 提供表、字段和记录的读取能力；公开的记录列表文档明确支持企业内部应用，并要求应用访问凭证和有资源权限的操作人身份。因此表单数据一旦成为目标数据表中的普通记录，理论上可由同一套记录 API 读取。但“表单提交记录是否与普通记录完全一致”及本项目当前权限是否实际生效，仍需实测。[列出记录][list-records] [SDK 类型][sdk-types] [SDK 实现][sdk-client]
- 官方公开资料没有明确确认：同一填写人重复提交时是否每次都新增独立记录、填写人与记录创建人的映射、修改已提交内容、单表单链接有效期或按填写人限制次数。以上均不得写成已确定能力。
- 本项目当前调用 Notable 2.0 API 仍受 `Notable.Base.Read` 与控制台 `Notable.Base.Read.All` 权限映射不一致阻塞。收集表单在界面内能落表，不代表后台服务已经能够读取或处理这些记录；两条链路必须分开验收。[AI 表格 API 调研][api-research]

## 能力核对

| 能力 | 当前结论 | 依据或下一步 |
|---|---|---|
| 创建收集表单 | **已确认** | 官方帮助中心说明表单用于数据收集；官方最佳实践明确要求创建表单视图。[记录、视图与表单][records-views-forms] [表单自动化最佳实践][form-automation-practice] |
| 表单提交沉淀为 AI 表格记录 | **已确认** | 官方最佳实践明确员工通过分享链接提交后，对比记录自动沉淀到 AI 表格，并使用“创建记录时”触发自动化。[表单自动化最佳实践][form-automation-practice] |
| 同一任务每次重复提交都新增独立记录 | **待实测** | 官方场景确认提交可创建记录，但没有定义同一填写人反复提交时的限制、覆盖或去重语义。PoC 需连续提交两次并检查记录数及记录 ID。 |
| 分享表单链接 | **已确认** | 官方最佳实践明确将 AI 表格的表单分享链接发送给员工。具体通过单聊发送不需要额外产品能力，但链接填写权限仍需实测。[表单自动化最佳实践][form-automation-practice] |
| 自动记录提交人 | **部分确认，映射待实测** | 记录 API 模型存在创建人信息，但未找到官方说明保证表单填写人一定等于记录创建人；匿名、免登录或代填场景尤其不能假定。不能用消息发送人替代表单提交人。[SDK 类型][sdk-types] |
| 自动记录提交时间 | **部分确认，语义待实测** | 记录 API 模型存在创建时间，但需实测表单记录是否稳定返回，以及它能否作为业务反馈提交时间。[SDK 类型][sdk-types] |
| 预填工单 ID | **能力已确认，具体链接待验证** | 官方规则为 `表单分享链接?prefill_问题名称=预填值`，支持文本字段和多题预填；工单 ID 可作为文本问题预填。PoC 需验证中文字段名编码、链接生成及被填写人修改后的处理。[表单预填默认值][form-prefill] |
| 允许同一人重复提交 | **待实测** | 未找到官方公开说明确认是否可限制次数，或重复提交是否生成新记录。PoC 需同一账号连续提交两次。 |
| 修改已提交内容 | **待实测** | 未找到官方公开说明确认填写者能否修改原提交。项目规则先采用“填错后重新提交，保留历史”，但需验证产品是否允许。 |
| 表单填写权限 | **待实测** | 当前官方 AI 表格表单资料没有完整说明填写范围、登录要求及填写人与表格协作者的关系；不能把其他钉钉表单产品的权限开关无条件外推到 AI 表格。 |
| 表单链接有效期/关闭 | **待实测** | 未找到官方公开的默认有效期或到期规则。需验证能否关闭收集、关闭后旧链接行为及是否可重新开放。 |
| 表单提交触发自动化 | **官方场景已确认，细节待实测** | 官方最佳实践使用“创建记录时”触发，随后更新记录和发送钉钉消息；动作顺序、失败重试和幂等仍需本项目验证。[表单自动化最佳实践][form-automation-practice] |
| 通过 API 读取提交记录 | **接口已确认，链路待实测** | Notable 记录列表文档支持企业内部应用，要求应用 token，且操作人需有目标 AI 表格权限；本项目仍有权限映射阻塞，尚不能证明表单提交后的记录可由当前应用读取。[列出记录][list-records] [SDK 实现][sdk-client] |
| 免费额度和限制 | **未确认** | 官方公开资料未给出本场景可依赖的免费行数、表单提交次数、自动化次数或 API 调用额度。出现付费或升级提示时必须停止并由用户确认。 |

## 推荐 PoC

### 阶段 1：表单填写与落表

在测试 AI 表格中创建收集表单，字段先保持最小：

```text
Teambition 工单 ID：必填文本
当前进度百分比：0–100 整数
当前情况：单选
风险原因与所需协助：长文本，可为空
```

仅在用户本人和已确定的测试人员范围内验证：

1. 生成并通过钉钉单聊发送表单链接；
2. 电脑端提交一次，手机端提交一次；
3. 同一账号对同一工单连续提交两次；
4. 确认每次提交是否新增独立记录，而不是覆盖原记录；
5. 检查是否自动保存可靠的提交人、提交时间和记录创建时间；
6. 验证关闭收集后旧链接的行为；
7. 检查是否出现付费、升级、次数或行数限制提示。

本阶段的完成标准是“填写后数据稳定进入测试 AI 表格”，不包括 Teambition 回写或生产通知。

### 阶段 2：读取、关联与自动化

在 Notable API 权限阻塞解决后再验证：

1. 选定并固定实际使用的 Notable API/SDK 版本，用官方记录列表接口读取两次表单提交；
2. 确认记录 ID、字段值、创建时间及提交人相关字段的真实结构；
3. 以必填工单 ID 关联 Teambition 任务；
4. 保留每次提交为反馈历史，按可靠时间字段选取最新反馈；
5. 验证 AI 表格自动化能否在提交后发送通知或更新任务主表；
6. 对自动化与后台处理分别设计幂等，避免一次提交触发重复更新。

开放平台网页中的旧版记录接口与第一方 `notable_2_0` SDK 在参数和权限表现上存在差异；实现时不能混用主机、请求头、操作人参数或权限名称，应以最终选定版本的官方契约和实际调用结果为准。[列出记录][list-records] [SDK 实现][sdk-client] [AI 表格 API 调研][api-research]

官方已给出预填链接规则，可为每个任务生成带工单 ID 的专属链接：

```text
表单分享链接?prefill_{URL 编码后的问题名称}={URL 编码后的工单 ID}
```

实际参数名必须与表单问题名称一致，并对问题名和值做 URL 编码。[表单预填默认值][form-prefill] 预填值属于填写便利能力，不是安全边界：提交后仍要校验工单存在、填写人负责关系和重复提交规则。

## 对项目流程的影响

收集表单方案的第一阶段数据流为：

```text
任务进入需要反馈的节点
→ 钉钉单聊发送收集表单链接
→ 开发人员填写并提交
→ AI 表格接收表单数据
→ 人工核对提交记录与工单 ID
```

API 和自动化验证通过后的目标数据流为：

```text
AI 表格产生反馈记录
→ 后台读取新记录
→ 按工单 ID 关联任务
→ 保留反馈历史
→ 最新有效记录更新任务主表
→ 计算风险并按规则通知
```

互动卡片和 Stream 回调保留为已完成的 PoC 记录，但不再是当前主方案，也不应继续消耗调试时间。

## 不应作出的假定

- 不假定分享链接天然只能由任务负责人填写；
- 不假定预填的 Teambition 工单 ID 不可被修改；
- 不假定提交人字段一定存在或可用作钉钉用户唯一标识；
- 不假定表单提交时间等于业务上的反馈生效时间；
- 不假定同一账号只能提交一次，或每次提交一定新增记录；
- 不假定界面内落表等于企业应用 API 可读；
- 不假定 AI 表格自动化具备可靠重试、严格顺序或天然幂等；
- 不假定测试应用、表单或自动化配置可以无差异迁移到正式环境；
- 不承诺免费、无限或长期不变的额度。
