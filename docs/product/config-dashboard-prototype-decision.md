# 配置库与管理看板产品原型决策

日期：2026-09-10

更新日期：2026-09-29

对应 Issue：#13

状态：行动中心、需求详情、工作单详情、版本详情、人员详情与异常与审计页已阶段确认；其他页面继续评审；不进入正式后台开发

## 原型问题与结论

本轮要回答的问题是：什么样的配置结构和看板布局，能让非技术项目负责人完成日常配置，并快速追踪版本、需求、风险和人员工作情况。

对比了三种可切换方案：A“行动驾驶舱”、B“配置工作台”、C“对象探索器”。最终不把三种方案建设成并列入口，而采用组合方案：

- A 作为默认首页，先呈现需要处理的风险、待协调人员、异常及指标可信度；
- B 作为独立配置库，集中维护系统默认、版本覆盖和需求级覆盖；
- C 的面包屑、父级上下文和横向信号矩阵吸收到统一对象详情中，树形浏览器不作为默认首页；
- 版本、需求、工作单和人员可保留父级上下文并继续下钻；各详情按对象职责展示必要信息，不强制采用完全相同的指标和侧栏。

## 已确认决策

### 配置库

1. 配置层级为“系统默认 → 版本覆盖 → 需求级覆盖”；下层只记录例外，未设置项继承上层。
2. 每个配置项必须展示生效值、来源层级、影响范围与变更记录；需求级覆盖支持恢复继承和发布前复核。
3. 版本启用前展示同步起点、覆盖数量和预计影响对象；版本结束后停止同步、采集和通知，但保留历史查询。
4. 状态语义映射按项目与工作流分组，保留原始状态 ID 和名称。新状态未映射时继续同步工作单，但暂停受影响的完成、历时、风险和通知。
5. 人员映射只由管理员确认。邮箱或手机号完全一致只能生成候选建议；仅姓名近似不得自动匹配。确认前禁止向候选人发送消息。

### 管理看板与异常

1. 默认首页按照管理行动排序，高风险、需关注、待协调人员、数据异常和数据覆盖率均可一跳进入对象详情或处理入口。
2. 业务风险、跟进风险和数据异常分别展示；人员并发关注是复核信号，不是绩效评分。
3. 风险展示当前等级、原因、影响节点、首次出现时间与持续工作日；解除后保留峰值和历史，不计算平均分。
4. “待处理异常”按状态未映射、人员待匹配、字段缺失或结构问题、同步失败和投递失败分组，展示编号、具体类型、对象、影响、发现时间、处理方和下一步；“审计记录”按时间倒序保留发现、重试、确认、修复和发布过程，两者通过异常编号关联。业务风险不混入数据异常。
5. 结束版本只进入历史查询，不进入默认行动队列。
6. 映射配置完成不直接关闭异常；待受影响数据同步、计算或校验确认恢复后才移出待处理。同步或投递重试成功也移出待处理，过程继续保留审计；异常页暂不增加详情抽屉、审计分类或筛选。

### 下钻与数据覆盖率

1. 版本 → 需求 → 工作单保留父级上下文；人员是从需求和工作单交叉进入的管理视角。
2. 四类详情保留面包屑与对象上下文，但指标、管理信号、最近变化和配置入口按对象分别设计；人员详情不设独立“当前管理信号”，改为本人相关的“最近变化”。
3. 数据覆盖率与指标并列显示，必须提供“可计算记录数 / 应统计记录数”、缺失原因和规则允许的排除项。
4. 覆盖率不低于 90% 为正常，70% 至 90% 为数据不完整，低于 70% 为指标暂不可靠。缺失值不按零处理，也不解释为低进度。

### 需求时间线与工作日历

1. 需求详情的工单时间线使用按日展开的日期网格和按周分组表头，横向状态条展示开始、截止与当前状态；周末、节假日和特殊工作日使用不同底色。
2. 时间线展示八类核心专业子单和测试总单；未排期工单仍保留在时间线中但不绘制日期条，点击工单打开右侧详情抽屉。
3. 工作日历支持将周末集体加班配置为特殊工作日，并统一影响计划周期、逾期、三日内到期、开发历时和测试历时。
4. 需求详情不展示结构完成率；保留终态工作单数量，但不将其换算为交付比例。

### 人员详情

1. 左侧人员列表按职能分组，可向左收起，点击姓名切换右侧详情；不产生人员排序、评分或排名。
2. 顶部只显示在手核心子单、并发关注、已逾期和三日内到期的数量，辅助来源说明不进入指标卡底部。
3. 工单明细分别展示所属需求、版本、计划时间、Teambition 状态和有效反馈进度；计划时间用红、绿、常规字体区分逾期、三日内到期和其他情况。
4. 右侧只保留与本人相关的最近变化，不重复展示独立管理信号；统计口径以本人实际执行的核心专业子单为准。

## 原型资产与验证范围

- 交互原型：`docs/prototypes/config-dashboard-prototype.html`
- 启动命令：`node scripts/serve-product-prototype.mjs`
- 方案切换：`?variant=A`、`?variant=B`、`?variant=C`，也可使用底部左右按钮或键盘方向键。
- 已走查版本配置、需求级覆盖、状态映射、人员映射、异常视图，及版本、需求、工作单、人员下钻。
- 原型只使用内存中的演示数据，不连接 Teambition 或钉钉，不包含持久化、鉴权、正式错误处理或后台服务。

## 后续边界

本决策可进入产品与技术规格编写。正式实现应按确认后的信息架构重新建设，并单独设计权限、保存发布、审计、接口和异常恢复；不得直接把本原型代码提升为生产代码。
