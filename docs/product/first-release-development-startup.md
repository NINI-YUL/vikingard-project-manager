用户确认：“是的已总原型V2为第一版目标”。第一版以总原型 v2 已验收的页面、功能、交互及已确认业务规则为整体交付目标，可以分批开发，不因分批而缩减已确认功能。

## 3. 第一版交付范围

| 模块 | 第一版需要具备的能力 | 判断是否完成的主要依据 |
| --- | --- | --- |
| 行动中心 | 风险、逾期、即将到期、风险工单执行人和数据待处理摘要 | 能从真实数据定位具体对象；未知不按零，业务风险与数据异常分开 |
| 版本管理与详情 | 选择、启用、范围查看、结束、移除、停止纳入与恢复纳入 | 遵守数据保留、上线事实、遗留工单及留档规则 |
| 需求与工作单详情 | 总览、时间线、其他直属工作单、反馈和状态历史、实际时间补录与修正 | 保留已确认字段、下钻、数据来源、权限和修正审计 |
| 人员详情 | 按实际执行者查看在手工作、并发关注、到期信息及最近变化 | 不把参与者的工单计为实际执行工作，不排名、不评分 |
| 配置库 | 规则分层继承、状态语义与恢复、日历、人员映射、业务角色和四档权限 | 校验、保存、继承、恢复验证和最后一名所有者保护有效 |
| 反馈与通知 | 钉钉发送任务专属 AI 表格链接，百分比反馈，提交校验及历史，按规则提醒和完成通知 | 正确的人反馈正确的任务；非法提交不更新业务数据，重复处理受控 |
| 异常与审计 | 与行动中心共享事项，版本及类型筛选，详情、处理入口、审计留存 | 异常按编号计数，受影响工单去重；确认恢复后移出待处理，过程保留 |
| 历史查询 | 已上线且选入留档版本的版本总览、版本详情和需求详情 | 日历、首次计划基线、实际日期、修正及延期原因遵循既定规则 |
| 人力参与度 | 年度和月度开发、调优、空闲与未知展示 | 使用可验证的人员关联与历史；证据不足不推为空闲，不作为工时或绩效 |
| 正式系统基础能力 | 真实登录与权限、持久保存、定时处理、同步可靠性、备份和运行状态监测 | 具体方案及验收方法在技术准备阶段补齐，不能用原型模拟代替 |

### 明确边界

- 不自动反向修改 Teambition 的状态、负责人、计划或任务内容。
- 不进行个人绩效评价、效率排名或平均风险评分。
- 不补造同步起点前的状态过程、实际时间或缺失数据。
- 不扩展常规采集到优化、测试、缺陷、验收或辅助工作单。
- 不增加特殊通知对象配置页；按已确认工单关系、业务角色及通知规则确定接收资格。
- 不擅自购买服务或升级付费方案。
- 里程碑反馈不在第一版范围。若移除原型中的里程碑演示，需要另行处理原型，不在本次文档任务中修改。

## 4. 人工、Teambition、钉钉和系统分别做什么

| 环节 | 人工操作 | 操作位置 | 系统自动处理 |
| --- | --- | --- | --- |
| 维护研发事实 | 创建、拆分任务，维护状态、职能、负责人、参与者和计划日期 | Teambition | 同步、校验结构并更新管理数据 |
| 纳入版本 | 负责人确认范围和首次计划，管理员选择、启用版本 | 本系统 | 读取当前快照，记录起点，检查异常 |
| 管理配置与权限 | 管理员维护规则、日历、角色和映射；所有者授予或撤销系统权限 | 本系统 | 执行权限校验、继承规则及审计 |
| 采集反馈 | 执行者从钉钉消息打开专属链接，填进度、情况及风险协助 | 钉钉 AI 表格收集表单 | 按时间和工作日规则发送，校验提交，保存历史、更新当前反馈 |
| 日常协调 | 负责人核实问题、协调资源与调整研发安排 | 业务沟通；事实变更回 Teambition | 展示风险、未反馈、并发和到期提示，按规则通知 |
| 修复数据问题 | 到源头补字段；管理员核实映射、补录时间或处理失败 | Teambition 或本系统对应入口 | 同步与验证恢复后移出异常，保留过程 |
| 阶段完成 | 负责人核实缺失职能是否确实不适用；相关人员执行测试和验收 | 本系统确认；Teambition 维护工作事实 | 根据规则判断节点、通知；重新打开时回退 |
| 版本结束 | 负责人确认实际上线等事实，管理员确认方式、遗留项和留档 | 本系统 | 退出常规同步、采集和通知，按结束类型保留记录 |

百分比 100% 不自动等于工作单已完成；完成以 Teambition 状态及已确认阶段规则判断。人员候选确认前不生效、不发送消息。保存状态映射后仍需验证恢复。

## 5. AI 表格首期建议与未定内容

以下保留 2026-11-04 的初始建议；截至 2026-11-06，已采用原有反馈表加“通知待发送表”完成测试，当前结果见上方验证进展。已确认的是“AI 表格主要承担反馈收集”，不承载本系统配置；本轮增加通知中转用途。

建议共用一张进度反馈记录表和一个收集表单，不按版本或人员拆表。五项业务字段沿用已确认填写规范：TB工单id、任务、当前进度百分比、当前情况、风险原因与所需协助。工单 ID 与任务标题系统预填；进度为 0–100 整数；有风险或阻塞时说明必填。

提交人身份、提交时间、原始记录标识需要平台可靠提供并经读取验证，不能用手填姓名代替可信身份。每次提交保留原始记录，后台分开处理校验结果、有效历史和当前反馈。

“采集请求标识”及其校验方式为建议，尚未确认；需验证提交如何对应正确采集轮次，不能将可编辑预填值直接当作可信凭据。表数量、元数据读取方式和条件必填能力在第 2 步验证后确定。
